# Перенос сайта «Доходные дома Ефремовых» на MODX 3

Установщик `bn-install.php` сам делает всё внутри MODX: ставит дополнения, копирует файлы сайта, создаёт шаблоны, поля, страницы, настройки и раздел «Заявки». Нужно только поставить сам MODX и один раз открыть установщик.

Что получится в админке:
- **Ресурсы → три дома** (Английский, Русский, Свиязева): все цены, гости, заезд и выезд, галерея, удобства, вопросы, тексты — во вкладке полей дома. Внутри каждого дома — его страница предоплаты (`/Предоплата1/` и т. д., адреса как на старом сайте).
- **Ресурсы → «Блог»** — статьи. Новая статья: правый клик по «Блогу» → «Создать документ», шаблон подставится сам. Текст пишется в визуальном редакторе: каждый раздел — заголовок «Заголовок 2», по ним строится оглавление.
- **Ресурсы → «Отзывы»** — отзывы гостей для карусели на главной и на страницах домов. Заголовок — имя гостя, «Содержимое» — текст отзыва слово в слово, в полях — дом, оценка, где оставлен, дата. Только настоящие отзывы.
- **«Конфигурация»** (ClientConfig) — телефоны, ссылка на чат MAX, ВКонтакте, почта на сайте и **почта для заявок**, реквизиты, скидка за бронь на сайте, процент предоплаты, залог, повар, ссылки для отзывов, Яндекс Метрика.
- **Пакеты → «Заявки»** — все заявки с сайта: статус (новая → связались → подтверждена → выехали / отказ), предоплата, заметка, выгрузка в Excel (CSV). Заявка «Подтверждена» занимает ночи дома — вторую заявку на те же ночи подтвердить не получится. На этой таблице потом можно построить онлайн-бронирование и календарь занятости.
- **Главная → поля**: фото первого экрана, частые вопросы, правила домов, лента фото. Тексты блоков главной — Элементы → Чанки → «Доходные дома / Главная».

Где будут файлы на хостинге (установщик раскладывает сам):
```
public_html/
  core/  manager/  connectors/  index.php      ← MODX
  core/components/bania/                       ← библиотека сайта и страница «Заявки»
  assets/css/  assets/js/  assets/img/         ← стили, скрипт, фото домов, QR-коды
```

## Шаг 1. Хостинг

1. В панели хостинга у домена выберите PHP **8.2** или **8.3**.
2. Выпустите бесплатный SSL-сертификат: сайт должен открываться по `https://`.

## Шаг 2. MODX 3

Поставьте MODX 3 (в панели Beget: **CMS → Установка CMS → MODX Revolution 3.x**, или вручную с [modx.com/download](https://modx.com/download) через `https://ваш-домен/setup/`). Запишите логин и пароль администратора.

## Шаг 3. Архив сайта

Загрузите `bania-modx.zip` в корень сайта (рядом с `index.php` MODX) и распакуйте. Появится папка `bania-modx`.

## Шаг 4. Установщик

1. Войдите в админку: `https://ваш-домен/manager/`.
2. В той же вкладке откройте `https://ваш-домен/bania-modx/bn-install.php?dry=1` — **проверка**, ничего не меняется. Красных строк быть не должно.
3. Нажмите **«Установить»** (1–3 минуты: скачиваются ClientConfig и визуальный редактор).
4. В конце установщик сам проверит сайт: страницы домов, предоплаты, блог, карту сайта, файлы, приём заявок, https и почту.
5. Нажмите **«Удалить папку установщика»**.

Проверьте сразу:
- главная, страницы домов, `/Предоплата1/`, `/kontakty`, `/blog` открываются;
- отправьте тестовую заявку с сайта — она придёт на почту из «Конфигурации» и появится в **Пакеты → Заявки**.

## Шаг 5. Что заполнить после установки

- **Почта для заявок** — «Конфигурация» → «Контакты». Можно несколько адресов через запятую.
- **Заявки в MAX** — бот, группа администраторов и мини-приложение: раздел «MAX» ниже.
- **Заявки в Telegram** (по желанию): создайте бота у @BotFather, добавьте его в нужный чат, впишите токен и ID чата в системные настройки `bn_tg_token` и `bn_tg_chat`.
- **Ссылки для отзывов** — «Конфигурация» → «Отзывы»: ссылки на ваши карточки в Яндекс Картах и 2ГИС, под каруселью появятся кнопки «оставить отзыв».
- **Яндекс Метрика** — «Конфигурация» → «Аналитика»: номер счётчика. Отправленная заявка считается целью `lead`.
- **Политика обработки персональных данных**: создайте страницу с шаблоном `bn-text` и текстом политики — форма и подвал ссылаются на неё.

## Как работать с сайтом

**Поменять цены.** Если установлено «Бронирование» — «Пакеты → Бронирование → Цены» (там же праздники; гости, заезд и выезд — во вкладке «Дома и бани»). Без него — Ресурсы → Дом → вкладка полей → «Цена Пн–Чт / Пт / Сб / Вс». Таблица на главной, карточки, расчёт в форме, разметка для поисковиков пересчитаются сами.

**Добавить фото дома.** «Медиа» → папка `assets/img/<код дома>/` (en — Английский, ru — Русский, sv — Свиязева) → загрузить. Затем в поле «Галерея» дома добавьте строку `имя-файла.jpg | подпись`. Порядок строк — порядок фото, **первые три строки — фото в карточке дома** (первая — главная).

**Удобства, вопросы, правила.** Одна строка — один пункт, части через `|`: `Вопрос | Ответ`, `значок | заголовок | пояснение`, `Название | значение`.

**Скидка.** «Конфигурация» → «Условия» → «Скидка за бронь на сайте». 0 — плашки скидки исчезнут.

**Отзыв.** Ресурсы → правый клик по «Отзывы» → «Создать документ». Порядок — перетаскиванием в дереве. Скрыть — снять «Опубликован».

**Тексты блоков главной** — Элементы → Чанки → «Доходные дома / Главная».

**Меню.** Шапка, выдвижное меню на телефоне и подвал собираются сами (сниппет `bnMenu`) из страниц верхнего уровня с галочкой «Показывать в меню», по «Позиции в меню»: Главная 0, Дома 1–3 (выпадающим списком «Дома»), Бронирование 20, Блог 30, Контакты 40. Новая страница в корне с галочкой появится в меню сама; чтобы встала между Блогом и Контактами — позиция 35. Название пункта — «Пункт меню» или заголовок страницы. Убрать пункт — снять галочку.

**Контакты.** Телефон, почта, ВКонтакте и ссылка на чат MAX — «Конфигурация» → «Контакты». На всех страницах меняются сразу. Пустая ссылка MAX — MAX на сайте не показывается.

**Площадки отзывов.** «Конфигурация» → «Отзывы»: ссылки на 2ГИС, Яндекс Карты и Авито по каждому Дому. QR-коды — картинки `assets/img/qr/rev-<дом>-<площадка>.svg`: после смены ссылки их нужно пересобрать (`py tools/make_qr.py`) и загрузить заново, иначе код поведёт по старому адресу.

## Учётные записи сотрудников

Установщик создаёт две группы и по четыре пользователя в каждой. Пароли случайные, их показывают **один раз** в конце установки: сохраните их сразу, в журнал на сервере они не пишутся. Пользователи, которые уже есть, не трогаются, их пароль не меняется. Создавать не нужно — запустите установщик с `?nomanagers=1` (в консоли `--no-managers`).

| Группа | Пользователи | Что можно | Чего нельзя |
|---|---|---|---|
| «Менеджеры сайта» | admin1–admin4 | страницы, публикация, тексты в чанках, фото и файлы, «Конфигурация», «Заявки», бронирование | дополнения, системные настройки, пользователи, шаблоны и сниппеты |
| «Бронирование» | booking1–booking4 | только «Пакеты → Бронирование»: календарь, заявки, Дома и бани, цены, праздники, закрытые даты | всё остальное, включая страницы, «Конфигурацию» и «Заявки» сайта |

Каждый может сменить пароль, имя и почту у себя: меню пользователя → «Профиль». Новому сотруднику — «Пользователи → Новый пользователь», группа «Менеджеры сайта» или «Бронирование», роль Member. «Конфигурацию» и «Заявки» сайта открывает только право `bn_site` (оно есть у администратора и у «Менеджеров сайта»); прямые ссылки на них без этого права закрывает плагин `bnAccess`.

## MAX: уведомления администраторам и приложение для гостей

### Как это устроено

- **Бот один, у него две работы.** Гостям он открывает бронирование прямо в MAX (кнопка мини-приложения). Администраторам от его имени сайт пишет в общую группу.
- **Группа администраторов — только для сотрудников.** В групповом чате MAX все участники видят все сообщения, а в сообщении о заявке есть имя и телефон гостя. Гостей в эту группу не добавляйте.
- **Гость видит только свою заявку**: в приложении по ссылке, которую получил после отправки, или по номеру заявки и телефону. Чужую заявку без телефона не открыть.
- **Что приходит в группу**: новая заявка (Дом или баня, даты и часы, гости, имя, телефон, сумма) и просьба гостя отменить бронь. То же самое — письмом на почту для заявок.
- **Бот отвечает гостю на общие вопросы** в личном чате — по данным сайта (раздел «Бот отвечает гостям на вопросы» ниже). О заявке гостю бот сам не пишет: подтверждение — звонок администратора. Статус заявки в чате — отдельная доработка.

### Шаг 1. Бот

Кабинет «MAX для бизнеса» → «Чат-боты» → ваш бот → «Настройки».

- «Добавление в групповые чаты» — **включено**, иначе бота не добавить в группу администраторов.
- **Токен доступа** вписывается только в админку сайта (шаг 4). Не пересылайте его в чатах и почте: с ним кто угодно пишет от имени бота. Если токен где-то засветился — кнопка обновления рядом с ним: старый перестанет работать, новый впишите в шаг 4.

### Шаг 2. Мини-приложение (поле «Введите ссылку»)

Заполняйте, **когда сайт уже работает на MODX на своём домене с https**:

```
https://ефремовскиебани.рф/booking/app?client=max
```

Если кабинет не примет русский адрес — тот же адрес латиницей: `https://xn--80abclabudnsrfxs3b.xn--p1ai/booking/app?client=max`. Кнопку открытия выберите «Открыть» и нажмите «Сохранить».

Пока сайт не перенесён, поле оставьте пустым: на копии GitHub Pages бронирования нет, мини-приложение открыло бы пустую страницу.

Метка `client=max` нужна, чтобы в заявке было видно: она пришла из MAX.

### Шаг 3. Группа администраторов

1. В MAX создайте группу, например «Администраторы Домов», и добавьте в неё сотрудников.
2. Добавьте в группу бота (поиск по его имени, например `@se13934569_2_bot`) и **назначьте администратором группы**, иначе он может не получить права писать.
3. Напишите в группе любое сообщение, например «проверка».
4. Узнайте номер (id) группы. На компьютере откройте PowerShell и выполните, вставив токен вместо `ТОКЕН`:

   ```
   Invoke-RestMethod "https://platform-api2.max.ru/updates" -Headers @{Authorization="ТОКЕН"} | ConvertTo-Json -Depth 10
   ```

   В ответе найдите `"chat_id"` рядом с названием группы: у групп это число со знаком минус, например `-71234567890123`. Если ответ пустой — напишите в группе ещё одно сообщение и повторите.

### Шаг 4. Настройки на сайте (дополнение MaxNotify3)

Если MaxNotify3 ещё нет — «Пакеты → Установщик» → поиск MaxNotify3 → установить. Затем «Настройки → Системные настройки», в фильтре выберите `maxnotify3`:

| Настройка | Значение |
|---|---|
| `maxnotify3.enabled` | Да |
| `maxnotify3.enable_sendit` | Да |
| `maxnotify3.provider` | `maxbusiness` (установщик сайта ставит сам) |
| `maxnotify3.max_api_url` | `https://platform-api2.max.ru/messages` — не меняйте |
| `maxnotify3.max_token` | токен бота из шага 1 |
| `maxnotify3.max_recipient_type` | `chat_id` |
| `maxnotify3.max_recipient_ids` | id группы из шага 3; несколько групп — через запятую |

Сохраните, «Управление → Очистить кэш», отправьте тестовую заявку с сайта: через несколько секунд она появится в группе. Не пришло — «Отчёты → Журнал ошибок», строки с `MAX` или `maxnotify3`. Заявка при этом всё равно сохранится в «Бронировании».

### Шаг 5. Администраторы в приложении (в том числе внутри MAX)

У каждого сотрудника свой ключ — так в истории заявки видно, кто её подтвердил.

1. Сотрудник входит в админку сайта **под своей учёткой** (admin1…, booking1…) → «Пакеты → Бронирование → Токены».
2. Подпись, например «MAX, Анна» → «Выпустить токен». Ключ показывается один раз — скопировать.
3. В MAX: бот → кнопка приложения → вкладка «Администратор» → вставить ключ → «Войти». Ключ запоминается на этом телефоне. В браузере и в установленном приложении на телефоне вход отдельный — тот же ключ можно вставить и туда.
4. Потерял телефон, уволился — в «Токенах» нажать «Отозвать». Ключ перестаёт работать сразу.

Ключ не отправляйте в общую группу — только себе в «Избранное» или лично.

### Бот отвечает гостям на вопросы

Гость пишет боту в **личный чат** — бот сразу отвечает и показывает кнопки: «Цены», «Заезд и выезд», «Дома», «Баня», «Правила», «Как добраться», «Контакты», «Забронировать». Переписку видят только гость и бот. В группах и каналах бот молчит.

**Откуда ответы** — только с вашего сайта, ничего не выдумывается:

| Что спрашивают | Откуда бот берёт ответ |
|---|---|
| цены, гости сверх нормы, питомцы, баня по часам, праздники | «Бронирование» → «Цены», «Праздники», «Дома и бани» |
| заезд и выезд, адреса, сколько мест | «Бронирование» → «Дома и бани» |
| бассейн, бильярд, бельё, мангал, Wi-Fi… | поле «Удобства» страницы Дома |
| частые вопросы (питомцы, залог, предоплата…) | поле «Частые вопросы» главной и страниц Домов |
| курение, шум, салюты, дети… | поле «Правила домов» главной |
| телефон, ВКонтакте, почта, скидка, повар | «Конфигурация» |

Поменяли цену или текст в админке — бот отвечает по-новому сразу. Хотите, чтобы бот знал ответ на новый вопрос, — добавьте его строкой в «Частые вопросы» (`Вопрос | Ответ`): он появится и на сайте, и в боте.

На непонятный вопрос бот честно отвечает «не нашёл» и даёт телефон администратора. Свободные даты не обещает — ведёт в бронирование.

**Проверить сейчас, без домена** (на компьютере, где работает сайт):

1. Токен бота — в системную настройку `maxnotify3.max_token` (шаг 4).
2. Командная строка в папке сайта:

   ```
   php core/components/booking/cli/bot.php ask "Сколько стоит Русский Дом?"
   ```

   покажет, что ответит бот, — без MAX.
3. Чтобы бот отвечал в настоящем MAX:

   ```
   php core/components/booking/cli/bot.php poll
   ```

   Пока окно открыто, бот забирает сообщения из MAX и отвечает (запасной режим). Напишите боту с телефона. Остановить — Ctrl+C. Компьютер выключен — бот молчит.

**На рабочем сайте** (домен с https):

1. «Системные настройки» → `booking.bot_enabled` = Да.
2. Один раз подключите вебхук — MAX сам будет присылать сообщения сайту:

   ```
   php core/components/booking/cli/bot.php subscribe https://ефремовскиебани.рф/assets/components/booking/bot.php
   ```

   Без SSH — попросите хостинг выполнить эту команду. Проверка: `php core/components/booking/cli/bot.php status`.
3. Запасной режим (`poll`) после этого не нужен и не работает: MAX отдаёт сообщения либо вебхуку, либо запасному режиму.

Выключить ответы — `booking.bot_enabled` = Нет. Уведомления о заявках в группу администраторов от этого не зависят.

### Шаг 6. Гостям

- Ссылку на бота (кабинет MAX → «Основная информация») впишите в «Конфигурация» → «Контакты» → MAX: на сайте появится значок MAX.
- Гость открывает бота → «Открыть» → вкладки «Забронировать» и «Моя заявка». Кнопка «?» внизу справа — инструкция для гостей; администратору после входа она открывается на разделе «Администраторам».
- Новости и акции — по желанию отдельный канал MAX. Для бронирования он не нужен.

## Fenom (pdoTools)

Сайт проверен с pdoTools 3: парсером pdoTools, Fenom в чанках (`pdotools_fenom_default`) и Fenom во всём содержимом страниц (`pdotools_fenom_parser`). Страницы, формы, бронирование, приложение и разметка для поисковиков работают одинаково во всех режимах. Свои вставки на Fenom в «Содержимое» можно писать как обычно; фигурные скобки сайта (JSON, скрипты) Fenom не трогает.

## Обновить сайт позже

1. На компьютере: `python tools/modx_build.py` → новый `dist/bania-modx.zip`.
2. Загрузите и распакуйте его (папку `bania-modx` можно заменить целиком).
3. Войдите в админку и откройте `https://ваш-домен/bania-modx/bn-install.php` → «Установить».

Обновится только изменённое. **Ваши правки не пропадут**: дома, статьи, отзывы, «Конфигурацию», заявки установщик не трогает; чанк или шаблон, который вы меняли в админке, он оставит как есть (новая версия ляжет в `core/cache/bn-install-backup/<дата>/new-versions/`).

**Бронирование** — отдельный пакет `booking-<версия>.transport.zip`. Новую версию: «Пакеты → Установщик» → «Загрузить пакет» → выбрать файл → «Обновить» (или «Переустановить», если версия та же). Заявки, брони, цены, праздники, Дома и бани, токены лежат в своих таблицах и при обновлении сохраняются; изменённые вами чанки бронирования (`booking.*`) пакет перезапишет — свои правки вносите в копии.

Ключи к адресу установщика: `?dry=1` — пробный прогон, `?check=1` — только проверить сайт, `?force=1` — перезаписать и изменённое в админке, `?update=1` — перезаписать ещё и страницы версиями из архива.

## Если что-то пошло не так

- **«Нужен вход в админку»** — войдите в `/manager/` в этом же браузере и обновите страницу установщика.
- **Ошибка дополнения** — поставьте ClientConfig и «TinyMCE Rich Text Editor» вручную: «Пакеты → Установщик», затем запустите установщик снова.
- **Письма не приходят** — заявки всё равно сохраняются в «Пакеты → Заявки». Отправитель писем — `noreply@ваш-домен`; другой — системная настройка `bn_email_from`.
- **Журнал установки** — `core/cache/logs/bn-install-<дата>.log`.

Из консоли SSH: `php bania-modx/bn-install.php --dry`, затем без `--dry`.
